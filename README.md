# Сайт Dmitry Astakhov | Serbia Market Entry & Trade Consulting

Статический трехъязычный сайт (английский, русский, сербский на латинице) на Astro. Цель сайта: чтобы поисковые системы и ИИ-ассистенты могли прочитать, понять и процитировать проверяемые сведения о консультанте и его услугах. Никаких гарантий позиций в Google, Яндексе или цитирования в ChatGPT сайт дать не может и не обещает.

Состояние на 9 ноября 2026 года: на https://dmitryasta.github.io/ опубликована версия от 30 октября. Версия для замены собрана и проверена локально, но на публичный адрес не выложена. В нее входят: коммерческое позиционирование, форма обратной связи через Formspree, обновленная политика конфиденциальности, правки для поиска и ИИ и новая 3D-визуализация первого экрана (три уровня: Белград, дистрибуция, импорт). Адрес формы Formspree вписан в сборку, но реальная доставка письма не подтверждена (тестовая отправка не проводилась). Как загрузить версию в репозиторий: файл `UPDATE_INSTRUCTION.md` в корне архива. Отчеты о проделанной работе: папка `reports/` в архиве.

## 2. Структура сайта

Адреса одинаковы на всех языках, различается префикс: английский в корне, русский в `/ru/`, сербский в `/sr/`.

- Главная, "Обо мне" (`about/`), обзор услуг (`services/`), обзор материалов (`insights/`), контакты (`contact/`), политика конфиденциальности (`privacy/`).
- Семь страниц услуг: `serbia-market-entry`, `find-distributors-in-serbia`, `import-to-serbia`, `export-from-serbia`, `local-commercial-representation`, `serbia-market-research`, `business-automation`.
- Семь статей: `how-to-enter-the-serbian-market`, `finding-distributors-in-serbia`, `importing-food-products-into-serbia`, `selling-to-serbian-retail-chains`, `serbia-market-research-before-you-ship`, `local-commercial-representation-in-serbia`, `russia-serbia-trade-agreements-for-exporters`.
- Итого 20 страниц на язык, 60 индексируемых страниц, плюс страница 404.

Технические файлы собираются автоматически: `sitemap.xml` (с языковыми альтернативами), `robots.txt` (поиск и ИИ-роботы разрешены), `llms.txt`.

## 3. Запуск и сборка на своем компьютере

Нужен Node.js 22 или новее.

```
npm ci
npm run dev        # режим разработки, адрес http://localhost:4321/
npm run build      # сборка в папку dist/ для адреса по умолчанию
npm run preview    # просмотр собранного сайта
```

Адрес и подпуть задаются переменными окружения `SITE_URL` и `BASE_PATH`. По умолчанию это `https://dmitryasta.github.io` и `/` (корень адреса). Имя пользователя GitHub `dmitryasta` указано по решению владельца; если оно изменится, замените его в `astro.config.mjs`. При публикации через GitHub Actions значения вычисляются автоматически (раздел 4).

Чтобы посмотреть сайт на корне локального адреса:

```
SITE_URL=http://localhost:4321 BASE_PATH=/ npm run build
npm run preview
```

Готовая сборка (папка `dist/`, в архиве она лежит в `extras/build/`) рассчитана на размещение в корне адреса `https://dmitryasta.github.io/`. Если открыть ее файлы двойным щелчком, ссылки не сработают: адреса страниц начинаются с косой черты и ищутся в корне диска, а не в папке. Для просмотра используйте `npm run preview`.

## 4. Бесплатная публикация на GitHub Pages

Эти шаги выполняет владелец сайта. Claude репозиторий не создавал и ничего не публиковал.

1. Создайте на GitHub репозиторий. Для бесплатного тарифа GitHub Pages работает из публичных репозиториев (условия тарифа проверьте на сайте GitHub).
2. Загрузите в него файлы проекта (без папок `node_modules`, `dist`, `qa`, `seo`). Обновление уже работающего сайта описано пошагово в файле `UPDATE_INSTRUCTION.md` в корне архива.
3. Откройте Settings, раздел Pages, и в пункте Source выберите GitHub Actions.
4. Отправьте изменения в ветку `main`. Workflow `.github/workflows/deploy.yml` соберет и опубликует сайт. Адрес публикации показан на вкладке Actions и в настройках Pages.
5. Откройте страницы всех трех языков, `sitemap.xml`, `robots.txt`, `llms.txt`.

Какое имя репозитория выбрать. Репозиторий нужно назвать `dmitryasta.github.io` (имя пользователя, точка, `github.io`). Сайт тогда откроется в корне адреса `https://dmitryasta.github.io/`, и `robots.txt`, `sitemap.xml` и `llms.txt` будут лежать там, где их ищут роботы. Если назвать репозиторий иначе, GitHub Pages разместит сайт в подпапке (`https://dmitryasta.github.io/имя-репозитория/`), workflow сам подставит этот подпуть, а три файла окажутся вне корня хоста: поисковые и ИИ-роботы не будут считывать их как правила сайта.

Собственный домен. Когда он появится, укажите его в Settings, Pages, Custom domain и добавьте в репозитории переменную `SITE_URL` (Settings, Secrets and variables, Actions, Variables) со значением `https://ваш-домен`. Workflow возьмет ее и соберет сайт с корневым путем `/`.

Откат. Если опубликована неудачная версия: на вкладке Actions откройте последний удачный запуск прежней версии и перезапустите его, либо выполните `git revert` для неудачного коммита и отправьте изменение. Перед заменой уже работающего сайта на новую версию подтвердите это у владельца.

## 5. Как менять содержимое

Контакты и основные факты: `src/lib/site.ts` (почта, LinkedIn, город). Эти значения попадают в текст, в JSON-LD и в `llms.txt`.

Тексты интерфейса (меню, подписи, страница "Обо мне", контакты, политика): `src/i18n/en.ts`, `ru.ts`, `sr.ts`. Структура трех файлов должна совпадать; при расхождении сборка завершится ошибкой с указанием места. Для материалов в `src/content` такой проверки при сборке нет: используйте `python3 qa/check_content.py`.

Услуги и статьи: файлы `src/content/<язык>/<идентификатор>.md`. В начале файла находится блок с полями (заголовок, описание, список вопросов и ответов, источники, связанные материалы), ниже текст в Markdown. Правила, которым следуют все материалы:

- title не длиннее 60 знаков, description не длиннее 160;
- у статьи есть `date` и, после проверки правил, `updated`;
- каждое утверждение о правилах и цифрах имеет источник в списке `sources` и дату проверки;
- внутренние ссылки между материалами относительные (`../slug/`);
- изменения вносятся сразу в три языка, затем запускается `python3 qa/check_content.py`.

Новая статья: добавьте идентификатор в `ARTICLE_IDS` в `src/lib/pages.ts`, создайте три файла `src/content/en|ru|sr/<идентификатор>.md`, добавьте ее в `relatedArticles` смежных статей и в `related` подходящей услуги, пересоберите сайт и запустите проверки (раздел 6). Предложения по темам и порядку публикаций: `seo/CONTENT_PLAN_6_MONTHS.md`.

Рекомендации. Раздел рекомендаций сейчас ведет на профиль LinkedIn и не цитирует отзывы. Добавлять текст рекомендации в `src/data/recommendations.ts` можно только после того, как он прочитан в профиле и есть согласие автора. Выдуманных отзывов быть не должно.

Фотография. Подлинной фотографии в сборке нет, и на сайте ее не показывают. Чтобы добавить, положите файл в `public/`, добавьте его на страницу "Обо мне" и в поле `image` разметки Person в `src/lib/schema.ts`.

Изображения для соцсетей (Open Graph): `python3 qa/og.py` создает три картинки 1200 на 630 в `public/og/`. Нужны Python и Playwright.

## 6. Проверки

Для проверок нужен Python 3 с пакетами `playwright`, `beautifulsoup4`, `openpyxl` и установленный Chromium (`playwright install chromium`).

```
SITE_URL=http://127.0.0.1:4380 BASE_PATH=/ npx astro build --outDir dist-qa
(cd dist-qa && python3 -m http.server 4380 --bind 127.0.0.1) &
python3 qa/check_content.py                                        # содержимое: структура ru/sr как у en, длины, стиль
python3 qa/check.py dist-qa http://127.0.0.1:4380                 # сборка: title, H1, canonical, hreflang, JSON-LD, ссылки, sitemap
python3 qa/shoot.py http://127.0.0.1:4380 qa/screens / /about/    # снимки и проверка горизонтальной прокрутки
python3 qa/seo_tables.py dist-qa seo                               # пересчет таблиц запросов и покрытия
```

Результаты и ограничения проверок описаны в `TEST_REPORT.md`.

## 7. После публикации

Порядок действий и сроки: `seo/SEO_MONITORING_PLAN.md`. Кратко: подключить Google Search Console, Bing Webmaster Tools и Яндекс Вебмастер (коды подтверждения владельца в проект кладет сам владелец), отправить `sitemap.xml`, добавить ссылки на сайт в профиль LinkedIn, через две-четыре недели собрать данные по показам и пересчитать приоритеты запросов, раз в 90 дней проверять актуальность правил в статьях.

## 8. Что нужно подтвердить владельцу до публикации

1. Статьи написаны по открытым источникам и требуют чтения самим Дмитрием. В тексте прямо помечены как непроверенные: судьба двустороннего соглашения России и Сербии 2000 года, регистрация импортера, обычные размеры платы за листинг в сетях, маршруты доставки Россия-Сербия. Формулировка переходного периода и номер Службени гласника поправок 2026 года по маркировке, различие агента и дистрибьютора (взято из вторичного обзора юридической фирмы) и содержание поправки ЕАЭС о прямой перевозке нужно проверить по первоисточнику.
2. Названия торговых сетей в статье о торговых сетях приведены как рыночные данные из публикации ESM Magazine от 7 сентября 2026 года с оговоркой, что автор сайта с ними не связан. Решение "не называть торговую сеть" касалось партнеров Дмитрия; подтвердите, что такой подход допустим, либо уберите таблицу.
3. Экспорт сербских товаров в резюме подтвержден слабо. Страница представляет эту услугу как проектную; проверьте формулировки.
4. "Ключевой результат" из резюме (восстановление оборота за девять месяцев и годовая выручка выше 2 млрд рублей, около 30 млн долларов) опубликован на странице "Обо мне" без названия компании. Подтвердите, что цифры можно публиковать.
5. Уровни языков (английский средний, сербский базовый с хорошим пониманием) взяты из резюме. Подтвердите или исправьте.
6. Описание текущего работодателя 2026 года намеренно общее. Расхождение между кратким описанием банковского опыта в LinkedIn и резюме на сайт не вынесено.
7. Фотографии нет. Рекомендации не показываются, сайт ведет на LinkedIn, где они читаются у авторов.
8. Адрес по умолчанию: `https://dmitryasta.github.io/` (по решению владельца). Он получится, если публичный репозиторий в учетной записи `dmitryasta` назван `dmitryasta.github.io`. Репозиторий создает владелец; Claude его не создавал и ничего не публиковал.
9. Подписи в интерфейсе (метки над заголовками, шапки таблиц) набраны обычным регистром, без принудительных заглавных. Если нужен вариант с заглавными, правится в `src/styles/global.css`.

## 9. Русские и сербские тексты

Русские и сербские версии подготовлены как переводы и адаптации английских материалов. Носитель языка должен прочитать их до публикации. Термины, в которых переводчики сомневались:

- русский: "практик коммерческих операций" (practitioner of commercial operations); названия сербских институтов и законов переданы собственными переводами; написание валют в падежах;
- сербский: "ukupni uvozni trošak" (landed cost), "Carinski zakon", сербское название Закона о торговых практиках для отдельных видов продукции взято из адреса источника, формы "rublji" и "rubalja" в тексте о рублях, названия институтов даны собственным переводом.

Официальные названия сербских законов и номера Службени гласника в статьях нужно сверить с первоисточником.
